# Кандидаты моделей и токен-бюджет

Статус: предварительный shortlist для эксперимента. Конкретные доступные версии, цены, региональность и условия хранения данных нужно проверить перед выбором. В этом окружении официальная страница OpenAI ответила 403, а страница Yandex Cloud — CAPTCHA; цены намеренно не выдуманы.

Названия — кандидаты, не рекомендация к production. Версии моделей и поддержка структурированного вывода должны быть зафиксированы в эксперименте.

## Сценарий и оценка токенов

Единица сравнения: пакет из 100 отзывов, средняя длина которого пока неизвестна. Для предварительного бюджета принимаем 60–100 токенов на отзыв и 700 токенов инструкций на вызов. При чанках по 20 отзывов получается около 6 700–10 700 входных токенов на 5 вызовов. Результат с меткой, кратким объяснением и ссылкой на исходные ID оценивается в 1 500–3 000 выходных токенов на пакет. Это грубая оценка; считать фактические токены нужно штатным tokenizer/API после получения данных.

Формула цены облачного сценария:

`cost = input_tokens / 1_000_000 * input_price + output_tokens / 1_000_000 * output_price`

Добавить 25% резерва на повторные запросы и исправление невалидного JSON. Не отправлять персональные данные. Локальный сценарий отдельно учитывает железо, энергопотребление, обслуживание и время ответа.

## Лимиты и деградация

- Ограничивать размер загрузки и длину одного отзыва; точные лимиты задать после прототипа.
- Разбивать пакет на чанки по 20, хранить ID исходных отзывов и версию промпта.
- При исчерпании бюджета не переключаться молча на платный провайдер: остановить новый анализ, сохранить уже обработанные чанки, сообщить пользователю и дать возможность продолжить после явного подтверждения.
- При timeout, ошибке API или невалидной схеме — ограниченный повтор; затем пометить чанк как не обработанный, не выдавать пустой ответ за успешный.
- Целевой лимит до проверки прайса: не более 20 ₽ на 100 отзывов и p95 не более 120 секунд. Это временные критерии из PRD, ожидают согласования и эксперимента.
